01

Wat is pyRevit — en wat is deze toolbar?

pyRevit is een gratis uitbreiding op Revit waarmee scripts als gewone ribbon-knoppen beschikbaar komen. Elke knop in de toolbar is een klein Python-script dat via de Revit API met het geopende model praat: elementen verzamelen, parameters lezen of schrijven, views en sheets aanmaken.

De BDJ Toolbar bundelt de scripts die het repeterende tekenkamerwerk overnemen — taggen, opschonen, views en sheets opzetten. Deze handleiding legt uit hoe de toolbar in elkaar zit en hoe je er zelf, veilig, een knop aan toevoegt.

Goed om te weten

pyRevit draait scripts standaard in IronPython 2.7. Dat is een ouder Python-dialect: moderne f"..."-strings werken er níet, en het delen van twee gehele getallen rondt af naar beneden. In hoofdstuk 07 staan de valkuilen op een rij.

02

Installatie & de toolbar koppelen

2.1 pyRevit installeren

  1. Download de nieuwste installer van github.com/pyrevitlabs/pyRevit/releases en installeer met de standaardinstellingen.
  2. Start Revit opnieuw. Er verschijnt een tabblad pyRevit in de ribbon.

2.2 De toolbar-extensie koppelen

  1. Zorg dat je de map van de toolbar-extensie hebt (de map die eindigt op .extension), lokaal of op de netwerkschijf.
  2. Ga naar pyRevit → Settings → Custom Extension Directories, voeg de map toe die de .extension-map bevat en klik Save Settings + Reload.
  3. Het toolbar-tabblad verschijnt in de ribbon. Zie je het niet: controleer of je de bovenliggende map hebt gekozen, niet de .extension-map zelf.
Reload = F5 van pyRevit

Na élke wijziging aan een script of mapnaam: pyRevit → Reload. Revit hoeft niet opnieuw op te starten — reload duurt een paar seconden en je wijziging is actief.

03

Mappenstructuur: mappen wórden knoppen

pyRevit bouwt de ribbon rechtstreeks uit de mappenstructuur op schijf. De naam van de map bepaalt de tekst in Revit; de extensie van de mapnaam bepaalt het type. Zo ziet de opbouw eruit:

MijnToolbar.extension/ └── MijnToolbar.tab/ ← het tabblad in de ribbon ├── 01_Views.panel/ ← een paneel (groep) op het tabblad │ ├── MijnKnop.pushbutton/ ← één knop │ │ ├── script.py ← de code (verplicht) │ │ ├── icon.png ← 32×32 px (aanbevolen) │ │ └── bundle.yaml ← extra opties (optioneel) │ └── Gereedschap.pulldown/ ← uitklapmenu met knoppen erin │ ├── ToolA.pushbutton/ │ └── ToolB.pushbutton/ └── 02_Handleiding.panel/ └── Handboek.urlbutton/ ← knop die een link/bestand opent └── bundle.yaml

3.1 De bundeltypes die wij gebruiken

MapextensieWat het oplevert
.pushbuttonEen gewone knop die script.py uitvoert. Het werkpaard van de toolbar.
.pulldownEen uitklapmenu; de .pushbutton-mappen erbínnen worden de menu-items (zo zijn de Tags- en Purge-menu's gebouwd).
.urlbuttonEen knop die een URL of document opent — bijvoorbeeld deze handleiding. Alleen een bundle.yaml met een hyperlink:-regel nodig.
.smartbuttonEen knop die zijn eigen icoon/status kan bijwerken op basis van het model (zoals de sections-toggle met drie standen).
.stackStapelt 2–3 knoppen verticaal binnen een paneel om ruimte te besparen.

3.2 Naamgeving

  • Panelen krijgen een nummerprefix (01_, 02_ …) — pyRevit sorteert alfabetisch, dus zo bepaal je de volgorde in de ribbon.
  • Knopmappen krijgen de Nederlandse knoptekst als naam; een \n in __title__ breekt de tekst op de knop af over twee regels.
  • Bestandsnamen en code: Engels. Teksten die de gebruiker ziet: Nederlands.
Let op

Hernoem of verplaats je een map, doe dan altijd een Reload en controleer of de knop nog werkt — een typfout in .pushbutton of een ontbrekende script.py laat de knop stilletjes uit de ribbon verdwijnen.

04

Anatomie van een script — het vaste sjabloon

Elk script in de toolbar volgt hetzelfde stramien, van boven naar beneden: header → imports → variabelen → config → main → rapportage. Wie één script kan lezen, kan ze daardoor allemaal lezen. Dit is het volledige, generieke sjabloon:

4.1 Waarom elk blok er staat

BlokFunctie
Header__title__ wordt de knoptekst, __doc__ de tooltip. De eerste regel (utf-8) is verplicht zodra er een é of ë in je teksten staat.
ImportsVast blok: Revit API via clr, en revit, forms, script uit pyRevit. Geen Dynamo-referenties (RevitServices) — die horen hier niet.
Variablesdoc, uidoc en output altijd bovenaan, zodat elk script dezelfde ingangen heeft.
ConfigAlle grenswaarden en namen als benoemde constante. Aanpassen kan dan zonder in de logica te graven.
MainVerzamelen → controleren → wijzigen. Wijzigen gebeurt altijd binnen with revit.Transaction("..."):.
ReportResultaten naar het output-paneel met output.print_md; pop-ups alleen voor echte fouten of bevestigingen.
05

De vijf gouden regels

Het doel achter alle conventies is één ding: een script mag Revit nooit laten vastlopen bij een collega. Deze vijf regels borgen dat:

  1. Wijzigen alléén via de context manager — with revit.Transaction("Nederlandse omschrijving"):. Gaat er iets mis, dan rolt Revit automatisch terug in plaats van in een open transactie te blijven hangen.
  2. Per element try/except Exception as e: in elke loop met een risicovolle actie. Eén kapot element mag nooit de hele batch afbreken; verzamel fouten en rapporteer ze.
  3. Cancel-check na elke keuzelijst. Klikt iemand op Annuleren, dan geeft forms.SelectFromList.show(...) None terug — controleer daarop en stop netjes met script.exit().
  4. Rapportage via output.print_md, niet via een pop-up per actie. Eén overzicht aan het einde, met output.linkify(element_id) zodat je naar elementen kunt doorklikken.
  5. Benoemde constanten in het CONFIG-blok — geen magische getallen of familienamen verstopt in de logica.
Zo herken je goed werk

Draait een script twee keer achter elkaar zonder dubbele resultaten, meldt het netjes wat het heeft overgeslagen, en overleeft het een klik op Annuleren — dan voldoet het aan de huisstijl.

07

Problemen oplossen

7.1 De knop verschijnt niet

  • Mapnaam eindigt exact op .pushbutton (of ander geldig type) en bevat een script.py.
  • De bovenliggende structuur klopt: .extension → .tab → .panel → .pushbutton.
  • Je hebt pyRevit → Reload gedaan na de wijziging.

7.2 Rode foutmelding (traceback)

Lees een traceback altijd van onder naar boven: de onderste regel zegt wat er misging, de regels erboven waar. De drie IronPython 2.7-klassiekers:

SymptoomOorzaak & oplossing
SyntaxError op een regel met f"..."F-strings bestaan niet in IronPython 2.7 — herschrijf naar "...{}".format(x).
Een deling geeft geruisloos een te laag geheel getalTwee gehele getallen delen rondt af naar beneden: 1850 / 1000 → 1. Maak er één een kommagetal van: / 1000.0.
Rare tekens of een fout bij é/ë in teksten# -*- coding: utf-8 -*- moet de allereerste regel van het script zijn.

7.3 "Er gebeurt niets"

Controleer het output-paneel (verschijnt achter het Revit-venster) — de meeste knoppen rapporteren daar in plaats van met een pop-up. Vindt een script niets om te doen, dan meldt het dat daar ook.

Gouden testregel

Test elke nieuwe of aangepaste knop eerst op een kopie van een echt project — niet alleen op een leeg testmodel, en nooit rechtstreeks op productiewerk.
